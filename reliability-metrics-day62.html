排行榜上的「成功率 65%」只回答了一个问题：它做得到吗？真正决定能不能把活交给 agent 的，是另一个问题：它每次都做得到吗？本期讲四个把「一次」和「每次」区分开的度量工具：pass^k、时长视界、风险率模型，以及尾部外推的不确定性。前置阅读：Day 15 评估与基准、Day 56 评测可复现性。

pass@k 与 pass^k：「至少一次」vs「每一次」pass@k vs pass^k

度量定义任务异质性
一句话类比

pass@k 像读多副本：k 个副本里任一个返回就算成功；pass^k 像串联调用链：k 次调用必须全部成功，整条链才算可用。同一个组件，两种组合方式给出的可用性天差地别。

它解决什么问题 + 工作机制

代码生成领域早就有 pass@k（Codex 论文，Chen et al. 2021）：对同一题采样 k 次，至少一次通过单元测试就算解出。这符合「有测试兜底、可以挑最好一份」的场景。但客服、下单、改数据库这类 agent 任务没有挑选的机会——每个真实用户只给一次机会。τ-bench（Yao et al. 2024）因此提出 pass^k：同一任务独立跑 k 次，全部成功才算。论文报告，即便是 GPT-4o 也只完成不到 50% 的任务，retail 域的 pass^8 更跌到 25% 以下。

两者都用无偏估计：每题跑 n 次、成功 c 次，则

  • pass@k = 1 − C(n−c, k) / C(n, k)：从 n 次里抽 k 次、一次都没成功的概率取补；
  • pass^k = C(c, k) / C(n, k)：抽出的 k 次恰好都落在成功里的概率。

关键直觉在任务异质性。若每题成功率都是 p，pass^k 就是 p^k，随 k 指数下滑；但现实中更常见的是「有些题永远对、有些题几乎永远错」。pass^k 是各题 p_i^k 的平均，不是平均 p 的 k 次方——前者衰减得慢得多。所以 pass^k 曲线的形状本身是诊断信号：曲线快速下滑说明失败是随机的、每次重来都可能换个结果；曲线很快变平说明失败集中在固定的一批题上，重来多少次都没用。

这也说明了重试为什么时灵时不灵。若各次尝试独立，k 次里至少成功一次的概率是 1 − (1 − p)^k，重试收益随 k 迅速累积；但这个公式的前提恰恰是「失败随机」。失败集中在固定任务上时，重试只是在同一个盲区里反复撞墙。换句话说，pass@k 与 pass^k 之间的差距，等价于告诉你有多少失败是「运气」、多少是「不会」。

代码示例
from math import comb

def pass_at_k(n, c, k): return 1 - comb(n - c, k) / comb(n, k)  # 至少一次
def pass_hat_k(n, c, k): return comb(c, k) / comb(n, k)        # 每一次

# 10 道题，每题跑 n=8 次：6 道每次都对，4 道 8 次里只对 1 次
n, succ = 8, [8]*6 + [1]*4
for k in (1, 4, 8):
    at  = sum(pass_at_k(n, c, k) for c in succ) / len(succ)
    hat = sum(pass_hat_k(n, c, k) for c in succ) / len(succ)
    print(f"k={k}: pass@k={at:.2f}  pass^k={hat:.2f}")
# k=1: 0.65 / 0.65   k=4: 0.80 / 0.60   k=8: 1.00 / 0.60

p = sum(succ) / (n * len(succ))
print(f"若失败完全随机，同样 65% 的 pass^8 = {p**8:.3f}")  # 0.032

同样是 65% 的单次成功率：失败集中时 pass^8 = 0.60，失败随机时只有 0.03。只报 pass@1 的榜单，把这两种系统看成同一个。

常见误区 + 实践场景
误区：「pass@k 高说明多试几次就行」。这只有在每次尝试相互独立、且有可靠的裁判挑出正确那份时才成立。没有裁判时，k 次输出里哪份对你并不知道；失败若集中在固定的题上，也根本不独立。
📌 BigCat 场景：评估一个日常用的 AI 工作流（例如每周自动整理投资笔记）时，别只看「这次结果好不好」，把同一输入跑 5 次，看结果是否每次都可接受。5 次全对的流程才配得上「自动化」三个字。
Takeaway + 思考题
💡 pass@k 衡量能力上限，pass^k 衡量可托付程度；两条曲线之间的缝隙，就是「会做」与「靠得住」的距离。
🤔 人类员工的 pass^k 通常远高于 pass@1 所暗示的水平，因为人会察觉自己出错。这种「自我察觉」应该算进模型能力，还是算进外部裁判？

时长视界：把可靠性折算成「能交多长的活」Task-Completion Time Horizon

METRlogistic 斜率
一句话类比

像延迟监控里的 p50 和 p99：同一个服务，按中位数看很快，按尾部看可能慢一个量级。时长视界的 50% 和 80% 就是可靠性的「中位数」与「尾部」。

它解决什么问题 + 工作机制

不同基准的成功率没法直接比较：SWE-bench 的 60% 和 τ-bench 的 60% 难度不同。METR（Kwa et al. 2025，arXiv:2503.14499）换了一个统一的尺子：请人类专家做同一批任务并记录用时，再问「模型在多长的任务上还有 50% 的成功率」。这个时长就是 50% 时长视界；把门槛提到 80%，得到 80% 时长视界。

做法是把成功率对任务时长的对数拟合一条 logistic 曲线：

P(成功 | 时长 t) = σ(α − β·ln t)

σ 是把任意实数压到 0–1 之间的 S 形函数；α 决定曲线在哪个时长跨过 50%（即模型多强）；β 是曲线的陡峭程度——β 大，成功率在某个时长附近陡降；β 小，成功率随时长缓慢衰减。解出两个视界后有一个简洁的结论：

h50 / h80 = 41/β

（4 来自 80%/20% 的赔率。）也就是说，50% 与 80% 视界之比只取决于斜率 β，与模型多强无关。β = 1 时比值是 4；β = 0.7 时就到了约 7 倍。早期论文中 Claude 3.7 Sonnet 的两个视界约为 59 分钟和 15 分钟，比值约 4。为什么用时长的对数？因为任务难度是乘法式增长的：从 1 分钟到 10 分钟，与从 1 小时到 10 小时，跨越的是同样的「数量级」。METR 也据此报告：前沿模型的 50% 视界自 2019 年以来大约每 7 个月翻一番。社区后续对更新模型的测算显示，这一比值并没有随能力提升而收窄，部分模型反而更大——曲线变得更平，长任务偶尔能做成，短任务却也偶尔失手。

成功率
100% ┤■■■■■■■□□
 80% ┤········■■□□□······ ← h80（尾部）
 50% ┤··················■■■□□····· ← h50（中位）
  0% ┼────────────────────────────▶ ln(人类用时)
β 越小（曲线越平），两条水平线之间的横向距离越大
代码示例
import math

def horizon(alpha, beta, q):
    # 解 σ(α − β·ln t) = q  →  ln t = (α − logit(q)) / β
    logit = math.log(q / (1 - q))
    return math.exp((alpha - logit) / beta)

for beta in (1.0, 0.7):
    alpha = beta * math.log(60)          # 让两条曲线的 h50 都是 60 分钟
    h50, h80 = horizon(alpha, beta, 0.5), horizon(alpha, beta, 0.8)
    print(f"β={beta}: h50={h50:.0f}min  h80={h80:.1f}min  比值={h50/h80:.1f}x")
# β=1.0: h50=60min  h80=15.0min  比值=4.0x
# β=0.7: h50=60min  h80=8.3min  比值=7.2x
常见误区 + 实践场景
误区：「50% 视界翻倍，就能放心交两倍长的活」。50% 视界衡量的是抛硬币水平的能力边界；能放手的区间要看 80% 甚至更高，而它可能只有前者的几分之一。另外两个视界来自同一条拟合曲线，并非独立测量。
📌 BigCat 场景：给 AI 分活时，用「人类做这件事要多久」来粗估风险：几分钟的小任务可以放手，接近半天的任务要拆成若干步、每步人工过目。拆分的意义就是把每一段都拉回高可靠区间。
Takeaway + 思考题
💡 时长视界把可靠性翻译成「能交多长的活」；50% 与 80% 之间的距离由曲线斜率决定，能力进步不会自动缩小它。
🤔 用人类用时当难度尺子，暗含「人类觉得难的，模型也觉得难」。对于「人类几秒、模型常错」的任务（比如数清字母），这把尺子会怎样失真？

风险率模型：失败是匀速发生的吗？Hazard Rate & Weibull Survival

生存分析一个被撤回的模型
一句话类比

像硬件可靠性里的浴盆曲线：新硬盘早期故障多，熬过「早夭期」之后反而稳定。问题是 agent 的失败更像「每分钟固定概率掉链子」，还是更像「开头最容易翻车」？

它解决什么问题 + 工作机制

时长视界是经验拟合，没说为什么成功率随时长下降。Toby Ord 2025 年给出了最简单的机制假设（arXiv:2505.05115）：风险率恒定（hazard rate：在「已经撑到此刻」的条件下，下一分钟失败的概率）。若每分钟失败概率固定，任务就像 n 个串联步骤，成功率 = p^n，呈指数衰减——像放射性衰变，50% 视界正好是 agent 的「半衰期」。这个模型漂亮之处在于一个参数就能推出所有视界。

2026 年初，Gus Hamilton 用生存分析里更一般的 Weibull 分布重新拟合了 METR 数据：

S(t) = exp(−(t/λ)k)

S(t) 是「撑过时长 t」的概率；λ 是时间尺度，对应模型强弱；k 是形状参数：k = 1 退化为恒定风险率，k < 1 表示风险率随任务推进而下降，k > 1 表示越做越容易出错。结果所有模型的 k 都显著小于 1，大致集中在 0.6 附近，而且模型变强时 k 几乎不变——进步主要体现在 λ 上。Ord 随后公开改变了看法，承认恒定风险率假设不成立。二手汇总还提到，人类基线的 k 更低（约 0.37），Hamilton 将其解读为人类更会自我纠错：熬过开头之后，后面越来越稳。

后果是不对称的：与同一 50% 视界的恒定风险率模型相比，k < 1 意味着超过视界的长任务比预想的好，短任务反而比预想的差——风险集中在任务开头（理解需求、选错路径）。

k < 1 还有一个与机制无关的统计来源，值得警惕：筛选效应。即便每类任务的风险率都恒定，只要把「容易的」和「困难的」任务混在一起，困难的那批会早早失败退出，活到后期的大多是容易的那批，于是总体风险率看起来在下降。生存分析里称之为异质性（frailty）效应。所以 k 小于 1 既可能意味着「模型越做越稳」，也可能只是「题目难度参差不齐」——要区分两者，需要在同一任务内部观察失败发生的时间点，而不只是看最终成败。

代码示例
import math

def survival(t, h50, k):
    lam = h50 / math.log(2) ** (1 / k)     # 让 S(h50) 恰好 = 50%
    return math.exp(-(t / lam) ** k)

for k in (1.0, 0.6):                     # 恒定风险率 vs 递减风险率
    row = [f"{t}min:{survival(t, 60, k):.2f}" for t in (5, 15, 240, 600)]
    print(f"k={k}", "  ".join(row))
# k=1.0 5min:0.94  15min:0.84  240min:0.06  600min:0.00
# k=0.6 5min:0.86  15min:0.74  240min:0.20  600min:0.06

两条曲线 50% 视界都是 60 分钟。k = 0.6 时，5 分钟小任务的成功率从 94% 掉到 86%，10 小时任务却从几乎为零升到 6%。

常见误区 + 实践场景
误区：「Weibull 拟合得更好，所以它就是真相」。多一个参数的模型总能拟合得至少一样好，Ord 本人也强调这一点；让他改变看法的是 k 在所有模型上都显著小于 1。它是更好的描述，不是已证实的机制。
📌 BigCat 场景：k < 1 提示风险集中在开头。和 AI 协作长任务时，把人的注意力前置：先审它对目标的复述与第一步计划，比在中途抽查更划算——这和带新人「头三天盯紧、之后放手」是同一个道理。
Takeaway + 思考题
💡 恒定风险率给了一个优雅的「半衰期」，但数据显示 agent 的风险随任务推进而下降；形状参数 k 比视界本身更能刻画「怎么失败」。
🤔 若 k 代表自我纠错能力，而模型变强时 k 几乎不动，那么「更强」和「更会纠错」也许是两种不同的进步。哪种训练信号可能直接改变 k？

尾部外推与测量噪声：99% 是测不出来的Tail Extrapolation & Evaluation Noise

不确定性模型选择 · 模拟器混杂
一句话类比

像用几百个请求样本去估 p99.99 延迟：数据根本没覆盖那个区间，得出的数字主要反映你选的分布假设，而不是系统本身；如果压测工具自己也会抖，测出的尾部还混着工具的噪声。

它解决什么问题 + 工作机制

真正关心可靠性时，我们想知道的是 99% 甚至 99.9% 的视界——这才是「能无人值守」的区间。但基准里的任务数有限，高可靠区间几乎没有数据点，只能靠曲线外推。两个来源的误差在这里叠加：

  • 模型形式误差：METR 默认的 log-logistic 曲线与 Weibull 曲线在 20%–80% 的中段几乎重合，Hamilton 指出它们在尾部显著分叉。下面的代码把两者校准到同一组 50%/80% 视界，到 99% 已经相差约 2 倍，到 99.9% 约 4 倍——而数据无法判定谁对。原因很朴素：要直接测出 99% 的成功率，得在那个时长附近积累数百个任务，误差才压得下去；而 1 次失败与 0 次失败之间，估计值就可能差出一大截。METR 2026 年的建模假设说明也列出了 Weibull 这种替代方案对视界估计的影响。
  • 环境噪声：pass^k 假设每次失败都怪 agent，但 τ-bench 类评测里「用户」本身是 LLM 扮演的。τ²-bench（Barres et al. 2025，arXiv:2506.07982）检查了用户模拟器，发现 retail 与 airline 域的模拟器出错率约 40% 与 47%，其中约 12% 与 13% 是足以让任务失败的严重错误；约束更强的 telecom 域只有 16%（严重 6%）。这部分失败会被算进 agent 头上，并在 pass^k 里按 k 次方放大。
代码示例
import math
h50 = 60.0; r = 6.6                        # 两模型共同的 h50=60min，h50/h80=6.6
inv_b = math.log(r) / math.log(4)          # log-logistic 的 1/β
k = math.log(math.log(2) / -math.log(0.8)) / math.log(r)  # Weibull 的 k（≈0.60）
for q in (0.8, 0.99, 0.999):
    ll = h50 / (q / (1 - q)) ** inv_b
    wb = h50 * (-math.log(q) / math.log(2)) ** (1 / k)
    print(f"{q:.1%}: log-logistic={ll:.4f}min Weibull={wb:.4f}min 比={ll/wb:.1f}x")
# 80.0%: 比=1.0x   99.0%: 比=2.2x   99.9%: 比=4.4x

p_agent, sim_crit = 0.90, 0.12             # agent 自身 90%，模拟器 12% 严重出错
for n in (1, 4, 8):
    print(n, round(p_agent**n, 2), round((p_agent * (1 - sim_crit))**n, 2))
# 1 0.9 0.79   4 0.66 0.39   8 0.43 0.15  ← 测到的 pass^8 只剩真实值约三分之一

第二段把模拟器错误简化为独立事件，只为示意「环境噪声在 pass^k 里会复利」。

常见误区 + 实践场景
误区：「报告给出了 99% 视界的点估计，就可以按它来规划」。尾部数字主要由分布假设决定，置信区间往往比点估计本身更有信息量；再加上测量环境的噪声，一个低 pass^k 可能有相当部分是裁判和陪练的问题。
📌 BigCat 场景：判断一项 AI 能力「够不够格」接手某件事时，问三个问题：数据覆盖了我关心的可靠性区间吗？换个合理的曲线假设，结论会翻转吗？失败里有多少来自评测环境本身？三问都答得上，数字才可信。
Takeaway + 思考题
💡 高可靠区间测不出来、只能推出来，而推法本身就是最大的不确定性；评测环境的噪声还会被 pass^k 成倍放大。
🤔 如果 99% 视界注定只能外推，「agent 已经可以无人值守地做 X」这种说法，应该要求什么样的证据才算成立？

深入思考

pass^k 的衰减曲线和 Weibull 的 k，说的是同一件事吗？
相关但不同。pass^k 看的是同一任务重复跑时的一致性，曲线变平说明失败集中在固定任务上，是「任务间异质性」；Weibull 的 k 看的是同一次运行内部风险随时间如何变化，是「过程内动态」。一个系统可以每次都在同一处翻车（pass^k 平、k 小），也可以每次随机翻车（pass^k 陡）。把两者放在一起，才能分清「它不会」和「它不稳」。
为什么分布式系统靠冗余能把 99% 堆到 99.999%，agent 却很难？
冗余堆可用性的前提是故障独立：两台机器同时坏的概率是各自概率的乘积。agent 多次尝试的失败往往高度相关——同一模型、同一误解、同一盲区，正是卡片 1 里那批「永远错」的题。冗余要奏效，需要真正异构的副本（不同模型、不同提示、不同方法）加一个可靠的裁判，这又把问题推回 Day 61 的「有没有硬裁判」。
人类 k 更低、更会自我纠错，这种能力来自哪里？
一种解释是元认知：人会在中途察觉「不对劲」并回退，所以熬过开头之后越做越稳。Hamilton 借用 Peto 悖论（体型巨大的鲸鱼并不因细胞多而更易患癌，因为演化出了更强的纠错机制）来类比。对模型而言，类似能力可能来自更好的自我验证与回溯；但如果 k 在代际间几乎不动，就说明单纯扩大规模没有自动带来这种能力。这也与佛学「正念」对念头的觉察有可对照之处：觉察本身就是一种纠错回路。
可靠性该由模型提供，还是由系统提供？
分布式系统给的答案很明确：用不可靠的组件搭可靠的系统，靠的是检测、重试、回滚和隔离，而不是要求每块硬盘都不坏。agent 领域的度量学在逼近同一结论——单个模型的 99% 视界又短又测不准，可靠性更可能来自外部结构。但前提是故障可检测：硬盘坏了会报错，agent 错了却常常流畅地给出错误答案（Day 60）。检测能力因此成为整条链路的瓶颈。
